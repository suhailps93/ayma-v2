These OVERRIDE assumptions in HACKATHON_PLAN.md where they differ.

## Hard rules (disqualification risks)
1. **New work only.** The demo may showcase ONLY features/code/functionality built Oct 26–Nov 4, 2026. Existing Ayma features must not be presented as hackathon work — the demo shows the Meta port + Practice Date only.
2. **Submitted repo must be PUBLIC.** Ayma main repo is private — we need a public repo containing the hackathon work (an official clarification for the "public repo with only the new components, private core" pattern was still pending in #questions as of Oct 26 01:07 PT; watch for the @CV answer).
3. One track only (we are Startup), one submission per team, solo OK (max team 4). One person submits for the team.
4. 18+, no policy violations, no third-party code/data/assets without rights.

## Judging (official)
- Gate: fits a problem statement (Build for Your World / Push the Frontier) AND meaningfully uses Meta Model API and/or Meta open-weight models.
- Scored EQUALLY on: **Impact · Use of Meta AI tooling · Technical depth and execution · Demo quality.** The 3-minute demo video is a main judging item. Top 5 per track advance to finals.
