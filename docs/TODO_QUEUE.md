- **Root cause:** on a **cascade** session (text chat LLM over the OpenAI-compatible protocol — LiveKit `inference.LLM`, or Meta Muse via `lk_openai.LLM`) an **agent-initiated** opener/greeting with no prior user turn built a **system-only** message list. `session.generate_reply(instructions=…)` adds the instruction as a *system* message, and LiveKit's OpenAI provider format (`_provider_format/openai.py::to_chat_ctx`) accepts but never applies `inject_dummy_user_message` (the google/anthropic/aws formats do), so the request reached the gateway with zero user/tool messages → 400. Realtime stacks (Gemini Live / Inference `RealtimeModel`) don't hit that request shape, which is why only the cascade/inference path fired.
- **Fix (`agent.py` + `prompt.py` + `prompts/voice_session_seed.md`):** every cascade proactive opener/greeting seeds one benign synthetic user turn via `generate_reply(user_input=prompt.load_voice_session_seed())`. Threaded as `seed_user_turn` through `_open_main_call` (welcome greeting + silent-caller opener), `maybe_open_conversation`, and the Practice Date greeting (`meta_cascade` only); `_start_main_cascade_session` passes `seed_user_turn=True`. Realtime paths leave it False → byte-identical opener/greeting. Seed text is a system cue the persona is told not to read aloud.
