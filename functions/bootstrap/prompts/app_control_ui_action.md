Operate one control on the user's current screen, exactly as if they tapped it. The screen context (current_screen in a call, the page context in chat) lists every operable control as [id] type "label" = state. Pass `control` (the id, e.g. s3), `label` (its exact label) and `action`: tap (buttons, links, list items, cards, chips, tabs, switches, checkboxes, radios), long_press, set_text (fields; `value` is the new text), increase/decrease (sliders), scroll_down/scroll_up (a list id, or none for the page; pass `value` as a repeat count 1-20 to move several screens in one call, e.g. "scroll down 3 times"), scroll_to_bottom/scroll_to_top (take a list, or none for the page, all the way to the end in ONE call — use this for "scroll to the bottom/top", "go to the end", "all the way down/up"; never chain single scroll_down/scroll_up steps for that), dismiss, or back (no control). Prefer open_screen/app_action when they cover the ask; use this for everything else on the page. Never for: deleting the account or any data for good, any purchase/subscribe/upgrade/trial/credits button, withdrawing face matching consent, any consent or terms checkbox or "I agree", passwords, codes or payment fields, or a confirmation dialog for any of those. For those, say kindly and briefly that the user needs to tap it themselves (open the page if they aren't on it). Sign out goes through account_action. Wipe what Ayma has learned is never done by Ayma at all: open Ayma's settings and tell them to tap it themselves. The "Unmute Ayma" control (shown while the user has told you to be quiet) may be tapped only when the user asks for it; never tap it on your own to end a quiet the user asked for. The return says whether it happened and what the screen shows now; relay it honestly. For scroll_to_bottom/scroll_to_top it says either it reached the end, or that it stopped early and more content may remain (a growing or paginated list) — relay that honestly rather than claiming it reached the end.
